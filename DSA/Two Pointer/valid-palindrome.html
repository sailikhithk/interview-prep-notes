2. Pattern Recognition

▶

Two Pointers — place one pointer at the start and one at the end, move them inward based on a comparison condition.

  • Symmetric comparison from both ends
  • In-place, O(1) extra space
  • Linear scan with shrinking window
  • Early exit on condition match / mismatch

3. Pattern Blueprint

▶
  1. 1Initialize left_index = 0, right_index = len(input_array) - 1
  2. 2While left_index < right_index: evaluate condition
  3. 3Move the pointer that improves the condition
  4. 4Track best answer / return on match

4. How to Think About It

▶

1. What is being compared? (sum, difference, area, equality, order)

2. Which pointer should move and why? (sorted input → move toward target; unsorted → move the limiting side)

3. When to stop? (pointers cross, target found, all pairs checked)

4. What to track? (max/min answer, matched pairs, valid window)

5. Real-World Analogy

▶

Two people at opposite ends of a shelf, walking toward each other. Each holds an item. They compare items at each step and decide who moves next based on what they're looking for.

Mappings: You = left_index, Friend = right_index, compare = the problem's condition, move = advance the pointer that doesn't satisfy the goal.

6. Build Your Intuition

▶

Q: Why not brute force? Brute force checks all pairs → O(n²) or worse. Two pointers exploit ordering to prune to O(n).

Q: Why does moving the smaller side work? The answer is bounded by the smaller side. Moving the larger side can only shrink the window without gaining height — no benefit.

7. How It Works (Step by Step)

▶
  1. 1Place left_index at index 0, right_index at last index
  2. 2Evaluate the problem condition on input_array[left_index] and input_array[right_index]
  3. 3Move the pointer that doesn't satisfy the goal inward
  4. 4Update the answer or return when condition is met

▶

Space: O(1)

Only two index variables and a few temporaries. No auxiliary data structures.

11. From Brute Force to Optimal — Every Decision & Why

▶

Each version below is forced by an edge case the previous version gets wrong. Read this as a chain of decisions, not a jump.

v0

Naive: direct compare

left_index, right_index = 0, len(input_string) - 1
while left_index < right_index:
    if input_string[left_index] != input_string[right_index]:
        return False
    left_index += 1; right_index -= 1
return True

Works on: "racecar", "abba"

Breaks on: "Aba" → 'A' != 'a' → false negative. Case is different but the letter is the same.

v1

+ Lowercase (fixes case)

left_index, right_index = 0, len(input_string) - 1
while left_index < right_index:
    if input_string[left_index].lower() != input_string[right_index].lower():
        return False
    left_index += 1; right_index -= 1
return True

Decision: Add .lower() before comparing. Now "Aba" → 'a' == 'a' → true. ✓

Breaks on: "A man, a plan, a canal: Panama" → input_string[1]=' ' != input_string[28]='m' → false negative. Spaces and punctuation aren't noise-insensitive.

v2

+ Pre-filter (fixes punctuation) — brute approach

cleaned_string = ''.join(char.lower() for char in input_string if char.isalnum())
left_index, right_index = 0, len(cleaned_string) - 1
while left_index < right_index:
    if cleaned_string[left_index] != cleaned_string[right_index]:
        return False
    left_index += 1; right_index -= 1
return True

Decision: Build a cleaned lowercase copy first, then two-pointer the copy. Now "A man..." → "amanaplanacanalpanama" → true. ✓

Cost: O(n) extra space for cleaned_string. The follow-up asks for O(1) space. We're correct but not optimal.

New edge case to consider: "4%554" → cleaned = "4554" → true. ✓ But isalpha() would have stripped the digits and given "" → true (wrong if digits mattered). So we chose isalnum(), not isalpha().

v3

+ Skip on the fly (fixes O(n) space)

left_index, right_index = 0, len(input_string) - 1
while left_index < right_index:
    while not input_string[left_index].isalnum(): left_index += 1
    while not input_string[right_index].isalnum(): right_index -= 1
    if input_string[left_index].lower() != input_string[right_index].lower():
        return False
    left_index += 1; right_index -= 1
return True

Decision: Don't pre-filter. Skip non-alphanumeric on the fly with inner while loops. Interleaves filtering with comparison — one pass, zero allocation. O(1) space. ✓

Breaks on: ".,:" (all non-alphanumeric) → left_index skips past right_index and keeps going → IndexError. Same for empty string.

v4

+ Guard the skip loops (fixes out-of-bounds) — FINAL

left_index, right_index = 0, len(input_string) - 1
while left_index < right_index:
    while left_index < right_index and not input_string[left_index].isalnum(): left_index += 1
    while left_index < right_index and not input_string[right_index].isalnum(): right_index -= 1
    if input_string[left_index].lower() != input_string[right_index].lower():
        return False
    left_index += 1; right_index -= 1
return True

Decision: Add left_index < right_index guard inside both skip loops. Now ".,:" → left_index and right_index cross inside the skip → outer while exits → true (vacuous palindrome). ✓

Handles everything: empty, single char, all-punctuation, mixed case + symbols, digits ("1A1"), "4%554", "A man, a plan, a canal: Panama". Time O(n), space O(1). Early exit on mismatch.

12. Common Mistakes

▶

● Moving the wrong pointer (the one that can't improve the answer)

● Forgetting to skip duplicates after finding a match

● Using ≤ instead of < in the while condition

● Not handling the case where input is not sorted (sort first or use a different approach)

13. Flashcards

▶

● Clarify sortedness: Ask if the input is sorted. If not, sort first (O(n log n)) then two-pointer.

● Narrate pointer movement: Explain why you move THIS pointer and not the other.

● Mention early exit: Return as soon as the answer is found — no need to scan the rest.

class Solution {
    public boolean isPalindrome(String s) {
        int l = 0, r = s.length() - 1;
        while (l < r) {
            while (l < r && !Character.isLetterOrDigit(s.charAt(l))) {  // First make 'l' point to any alphanumeric
                l++;
            }
            while (l < r && !Character.isLetterOrDigit(s.charAt(r))) {  // First make 'r' point to any alphanumeric
                r--;
            }
            if (Character.toLowerCase(s.charAt(l)) != Character.toLowerCase(s.charAt(r))) {
                return false;
            }
            l++;
            r--;
        }
        return true;
    }
}

class Solution {
    public boolean isPalindrome(String s) {
        // Remove non-alphanumeric characters and convert to lowercase
        StringBuilder sb = new StringBuilder();
        for (char c : s.toCharArray()) {
            if (Character.isLetterOrDigit(c)) {
                sb.append(Character.toLowerCase(c));
            }
        }
        
        String cleanedString = sb.toString();
        // Check if the cleaned string is equal to its reverse
        return cleanedString.equals(new StringBuilder(cleanedString).reverse().toString());
    }
}

20. Follow-Up Questions

▶
What if the input is not sorted?

Sort first (O(n log n)) then apply two pointers. Or use a hash map for O(n) time + O(n) space.

What if there are duplicates?

After finding a match, skip consecutive duplicate values on both pointers to avoid duplicate answers.

Can you do it in one pass?

Yes — two pointers IS one pass. Each element is visited at most twice total (once by each pointer).
