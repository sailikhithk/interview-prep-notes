Remove Duplicates from Sorted Array

Time: O(n) Space: O(1) Two Pointers

1. Problem Statement

You are given an integer array nums sorted in non-decreasing order. Remove the duplicates in-place so that each element appears only once, preserving the original relative order. Return k, the count of unique elements.

The first k positions of nums must contain the unique elements in sorted order. Values beyond index k-1 are ignored.

Constraints:

  • 1 ≤ nums.length ≤ 3 × 10^4
  • -100 ≤ nums[i] ≤ 100
  • nums is sorted in non-decreasing order

Example: Input: nums = [0,0,1,1,1,2,2,3,3,4] → Output: 5, nums = [0,1,2,3,4,_,_,_,_,_]

The first 5 positions hold [0,1,2,3,4]. The remaining positions are irrelevant.

2. Pattern Recognition

▶

Signal words: "sorted array", "remove duplicates", "in-place", "return the count", "preserve order". Any problem asking for in-place modification of a sorted array to keep unique elements is a two-pointer overwrite problem.

When to reach for this pattern: Whenever the input is sorted and you must deduplicate or partition in-place with O(1) extra space. The sorted property guarantees that duplicates are adjacent, so a single sweep with a "write pointer" suffices.

Key insight: Use a write pointer (last_distinct_index) marking where the next unique element should be placed. A read pointer (scan_index) scans forward. When nums[scan_index] differs from the last written element, write it at last_distinct_index and advance the write pointer.

  • Sorted input → duplicates are adjacent
  • In-place requirement → overwrite, don't allocate
  • Two pointers: read scans, write places uniques

Approaches considered before settling on two pointers: Always brainstorm variants before committing. The sorted + in-place constraints rule out most of them, but naming them forces you to understand why the chosen pattern wins.

3. Pattern Blueprint

▶
  • 1Initialize last_distinct_index = 0 (first element is always unique)
  • 2For each scan_index from 1 to n-1:
  • 3If nums[scan_index] != nums[last_distinct_index]: it's a new unique
  • 4Increment last_distinct_index, then nums[last_distinct_index] = nums[scan_index]
  • 5Return last_distinct_index + 1 (count of uniques)

4. How to Think About It

▶

Because the array is sorted, all duplicates of a value sit next to each other. So a single left-to-right scan sees each unique value as the first element of a run.

Maintain a "write frontier" last_distinct_index. Everything at index ≤ last_distinct_index is the deduplicated prefix. The read pointer scan_index walks the array. Whenever it finds a value larger than nums[last_distinct_index], that value is a new unique, so we advance the write frontier and copy it in.

This is an overwrite pattern, not a swap pattern. We never need to read what we overwrite, because the read pointer is always ahead of the write pointer (or equal). The uniques are preserved in sorted order because we copy them in the order we encounter them.

5. Real-World Analogy

▶

Imagine a librarian shelving returned books that arrive pre-sorted by ID. Whenever the same book ID arrives twice in a row, the librarian skips the duplicate and only shelves the first copy. The shelf stays sorted and has no duplicates.

The librarian uses one hand to point at the next empty shelf slot (the write pointer) and the other to flip through the incoming stack (the read pointer). When a new ID shows up, it goes to the next empty slot.

Mappings: incoming stack = nums, next-empty-slot hand = last_distinct_index, flip-through hand = scan_index, shelving a new ID = nums[++last_distinct_index] = nums[scan_index].

8. How It Works (Step by Step)

▶
  • 1Initialize last_distinct_index = 0. The first element is always unique.
  • 2Loop scan_index from 1 to len(nums) - 1
  • 3Compare nums[scan_index] with nums[last_distinct_index]
  • 4If different: increment last_distinct_index, copy nums[scan_index] into nums[last_distinct_index]
  • 5Return last_distinct_index + 1 as k

10. From Brute Force to Optimal — Every Decision & Why

▶

v0 — Brute Force: new array, then copy back

Time: O(n) Space: O(n) 
def removeDuplicates(self, nums: List[int]) -> int:
    unique_values = []
    for value in nums:
        if not unique_values or value != unique_values[-1]:
            unique_values.append(value)
    for i, value in enumerate(unique_values):
        nums[i] = value
    return len(unique_values)

Fails on: The constraint "in-place, O(1) extra space". This allocates O(n) auxiliary memory. Time O(n), Space O(n) — rejected by the judge's memory check.

v1 — Two pointers, nested while for duplicate runs

Time: O(n) Space: O(1) 
def removeDuplicates(self, nums: List[int]) -> int:
    n = len(nums)
    left_index, right_index, last_distinct = 0, 1, 0
    while right_index < n:
        while right_index < n and nums[left_index] == nums[right_index]:
            right_index += 1
        if right_index < n:
            nums[last_distinct + 1] = nums[right_index]
            last_distinct += 1
        left_index, right_index = right_index, right_index + 1
    return last_distinct + 1

Enhancement: In-place, O(1) space. The inner while looks nested but is O(n) amortized — right_index only moves forward (never resets), so total pointer movements across both loops is n-1. Time is O(n), same as v_final. The cost is code clarity: three variables and a nested loop = more state to track than needed.

Edge case handled: All-duplicates [1,1,1] → inner while advances right_index to n, outer loop exits, returns 1. Correct.

v_final — Single pass, write pointer + read pointer

Time: O(n) Space: O(1) 
def removeDuplicates(self, nums: List[int]) -> int:
    last_distinct_index = 0
    for scan_index in range(1, len(nums)):
        if nums[scan_index] != nums[last_distinct_index]:
            last_distinct_index += 1
            nums[last_distinct_index] = nums[scan_index]
    return last_distinct_index + 1

Why final: O(n) time, O(1) space, single pass, two variables. The for loop naturally advances the read pointer; we only act on a difference. Same asymptotic cost as v1 but cleaner state. This is the version used in Section 20.

11. Complexity Deep Dive

▶

Time: O(n)

The read pointer scan_index visits each element exactly once from index 1 to n-1. Constant work per step (one compare, one conditional write). Total: O(n).

Space: O(1)

Only two scalar variables: last_distinct_index and scan_index. All modification happens in the input array — no auxiliary data structures.

12. Edge Cases & Gotchas

▶
Single element (n = 1): Loop doesn't run, returns 0 + 1 = 1. Correct.
All duplicates: [7,7,7,7]. Read pointer scans, never differs from nums[0], write pointer stays at 0. Returns 1. Correct.
No duplicates: [1,2,3,4]. Every step writes, write pointer tracks read pointer. Returns 4. Correct.
Negative values: [-3,-3,-1,0,0,2]. Sorted order holds, comparisons work. Returns 4 ([-3,-1,0,2]). Correct.
Off-by-one bug: Return last_distinct_index + 1, NOT last_distinct_index. The index is 0-based; the count is index + 1.
Compare against last written, not last read: Compare nums[scan_index] with nums[last_distinct_index] (the deduplicated prefix's tail), not with nums[scan_index - 1]. They're equivalent here only because the array is sorted; using the write pointer is the canonical pattern.

13. Common Mistakes

▶
  • Allocating a new array (violates the O(1) space constraint)
  • Returning last_distinct_index instead of + 1 (off-by-one on the count)
  • Comparing nums[scan_index] with nums[scan_index - 1] instead of nums[last_distinct_index] (works only because sorted; wrong habit for the general pattern)
  • Incrementing last_distinct_index before writing (overwrites the wrong slot)
  • Starting scan_index at 0 (redundant compare with self, and the first element is always unique)

14. Flashcards

▶

Q: Why does the sorted property matter?

A: Sorting makes duplicates adjacent, so a single left-to-right sweep with one read pointer catches every duplicate run. On an unsorted array, duplicates could be anywhere and this pattern wouldn't work.

Q: What does the write pointer represent?

A: last_distinct_index is the index of the last placed unique element. Everything at index ≤ last_distinct_index is the deduplicated prefix. The next unique goes at last_distinct_index + 1.

Q: Time and space complexity?

A: O(n) time (one pass), O(1) space (two scalars, in-place).

Q: Why return last_distinct_index + 1?

A: The index is 0-based. If the last unique is at index k-1, the count of uniques is k.

Q: Can the read pointer ever fall behind the write pointer?

A: No. scan_index starts at 1 and only increases; last_distinct_index starts at 0 and only increases when a new unique is found, so scan_index ≥ last_distinct_index always. We never overwrite a value we still need.

19. Where This Pattern Meets System Design

▶

Time-series compaction: A sorted-by-timestamp event log often has back-to-back duplicate readings (e.g., a sensor reporting the same value every tick). An in-place write-pointer pass collapses runs before storage, cutting disk usage without allocating a new buffer.

Sorted index pages in databases: B-tree leaf pages store sorted keys. When maintaining a unique index, the storage engine uses an in-place compaction pass to remove duplicate keys during page rewrites, avoiding a full page copy.

Stream deduplication at the edge: Edge devices with limited memory can't afford to buffer a full set. If the stream is pre-sorted (e.g., by event ID), a write-pointer pass deduplicates in O(1) extra memory before forwarding upstream.
