Sort Array By Parity

Time: O(n) Space: O(1) Two Pointers

1. Problem Statement

Given an integer array nums, move all the even integers to the beginning followed by all the odd integers. Return any array that satisfies this condition.

Constraints:

  • 1 ≤ nums.length ≤ 5000
  • 0 ≤ nums[i] ≤ 5000

Example: Input: [3,1,2,4] → Output: [2,4,3,1] (or [4,2,1,3], etc.)

2. Pattern Recognition

▶

Signal words: "move all even", "followed by odd", "any array that satisfies", "in-place" (implied by follow-up).

When to reach for this pattern: Whenever you need to partition an array into two groups (even/odd, positive/negative, zero/non-zero) and order within each group doesn't matter.

Key signal: "any array that satisfies" → order doesn't matter → in-place swap is allowed → two pointers.

  • Partition problem (two groups)
  • Order within groups doesn't matter
  • In-place, O(1) extra space possible

3. Pattern Blueprint

▶
  • 1Place left_index at 0, right_index at last index
  • 2While left_index < right_index:
  • 3If nums[left_index] is odd and nums[right_index] is even → swap, move both
  • 4If nums[left_index] is even → left_index++
  • 5If nums[right_index] is odd → right_index--

4. How to Think About It

▶

The key insight is that order doesn't matter within each group. The problem says "any array that satisfies this condition" — that's the signal that we can swap freely.

If order mattered, we'd need a stable partition (preserve relative order) and two pointers wouldn't work — we'd need extra space. But since order doesn't matter, we can use the Dutch flag style two-pointer sweep.

Think of it as: left_index hunts for an "out of place" odd number in the even zone. right_index hunts for an "out of place" even number in the odd zone. When both find one, swap. Continue until they meet.

5. Real-World Analogy

▶

Imagine sorting a deck of cards into red and black piles, but you don't care about the order within each pile. You fan the deck out, point at the leftmost card with your left hand and the rightmost with your right hand.

Left hand moves right until it finds a black card in the red zone. Right hand moves left until it finds a red card in the black zone. Swap them. Repeat until your hands meet.

Mappings: You-left = left_index, You-right = right_index, red = even, black = odd, swap = exchange the two cards.

Notice: evens first ([4,2]), odds last ([1,3]). Order within each group is whatever the swaps produced.

9. Complexity Deep Dive

▶

Time: O(n)

Each element is visited at most once. left_index only moves right, right_index only moves left. They meet in the middle after at most n comparisons total.

Space: O(1)

In-place swaps. Only two index variables and a temp for the swap. No extra arrays.

10. From Brute Force to Optimal — Every Decision & Why

▶

Each version is forced by an edge case the previous version fails on (or a cost it can't afford).

v0

Naive: two separate lists

even_list = []
odd_list = []
for val in nums:
    if val % 2 == 0:
        even_list.append(val)
    else:
        odd_list.append(val)
return even_list + odd_list

Works on: everything. Correct and simple.

Breaks on: the follow-up "can you do it in-place?" — uses O(n) extra space. Also two passes when one would do.

v1

+ In-place swap (fixes space)

left_index, right_index = 0, len(nums) - 1
while left_index < right_index:
    if nums[left_index] % 2 != 0:
        nums[left_index], nums[right_index] = nums[right_index], nums[left_index]
        right_index -= 1
    else:
        left_index += 1
return nums

Decision: Swap odd-at-left with whatever is at right, then shrink right. If even-at-left, advance left. O(1) space, O(n) time. ✓

Breaks on: [1,2,3,4] → left=0 (1, odd), right=3 (4, even) → swap → [4,2,3,1], right=2. Now left=0 (4, even) → left=1 (2, even) → left=2 (3, odd), right=2 → swap with self, right=1. left=2, right=1 → stop. Result [4,2,3,1]... actually works but does unnecessary swaps when right is already odd. Not a correctness bug, but a wasted-swap inefficiency.

v2

+ Skip-forward on both sides (fixes wasted swaps) — FINAL

left_index, right_index = 0, len(nums) - 1
while left_index < right_index:
    while left_index < right_index and nums[left_index] % 2 == 0:
        left_index += 1
    while left_index < right_index and nums[right_index] % 2 == 1:
        right_index -= 1
    nums[left_index], nums[right_index] = nums[right_index], nums[left_index]
return nums

Decision: Before swapping, skip left_index forward past any already-even elements, and skip right_index backward past any already-odd elements. Only swap when both are out of place. No wasted swaps. ✓

Handles everything: all-even, all-odd, single element, empty (via constraint), already-partitioned. Time O(n), space O(1).

11. Edge Cases & Gotchas

▶

All even: [2,4,6,8] → left_index skips to end, no swaps, return as-is.

All odd: [1,3,5,7] → right_index skips to start, no swaps, return as-is.

Single element: [2] → left=0, right=0, loop doesn't enter, return [2].

Already partitioned: [2,4,1,3] → skip-forward handles it, no swaps needed.

Alternating: [1,2,3,4] → swaps (1,4) then (3,2) → [4,2,1,3].

Zeros: 0 % 2 == 0 → zero is even. Handled.

12. Common Mistakes

▶

● Forgetting the inner while loops and swapping every time left is odd — works but does unnecessary swaps.

● Not checking left_index < right_index inside the inner while loops → can go out of bounds or cross over.

● Using left_index ≤ right_index in the outer loop → one extra swap of the middle element with itself.

● Modifying the array when the problem expects a new array (read the problem — this one allows in-place).

● Using nums[i] % 2 == 1 for odd — breaks on negative numbers in some languages (Python is fine, but Java -3 % 2 == -1). Use != 0 for safety.

class Solution:
    def sortArrayByParity(self, nums: List[int]) -> List[int]:
        left_index, right_index = 0, len(nums) - 1
        while left_index < right_index:
            while left_index < right_index and nums[left_index] % 2 == 0:
                left_index += 1
            while left_index < right_index and nums[right_index] % 2 == 1:
                right_index -= 1
            nums[left_index], nums[right_index] = nums[right_index], nums[left_index]
        return nums

Python (v0 — two lists, O(n) space)

class Solution:
    def sortArrayByParity(self, nums: List[int]) -> List[int]:
        even_list = [val for val in nums if val % 2 == 0]
        odd_list = [val for val in nums if val % 2 != 0]
        return even_list + odd_list
