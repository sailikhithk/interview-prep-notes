Container With Most Water

Time: O(n) Space: O(1) Two Pointers

1. Problem Statement

You are given an integer array height of length n. There are n vertical lines drawn such that the two endpoints of the i-th line are (i, 0) and (i, height[i]). Find two lines that, together with the x-axis, form a container that holds the most water. Return the maximum amount of water a container can store.

Constraints:

  • n ≥ 2
  • 0 ≤ height[i] ≤ 10^4

Example: Input: height = [1,8,6,2,5,4,8,3,7] → Output: 49

The container between index 1 (height 8) and index 8 (height 7) holds min(8,7) * (8-1) = 7 * 7 = 49 units of water.

2. Pattern Recognition

▶

Signal words: "maximum amount of water", "two lines", "container", "x-axis forms a container". Any problem asking for the max/min of a function over pairs with a geometric constraint (area = width × limiting height) is a two-pointer candidate.

When to reach for this pattern: Whenever you are optimizing over pairs of elements and the objective is a product of (distance between them) and (a min/max of their values). The two-pointer sweep works because moving the limiting pointer is the only way to potentially improve.

Key insight: The widest container (first and last line) is the best starting candidate by width. Moving the taller pointer inward can only shrink width without raising the water level, so it is never useful. Move the shorter pointer inward, because it is the bottleneck.

  • Optimization over pairs (area = width × min height)
  • Greedy elimination: the shorter line can never do better
  • Two pointers from both ends, O(n) sweep

3. Pattern Blueprint

▶
  • 1Place left_index = 0, right_index = len(height) - 1 (widest container first)
  • 2While left_index < right_index:
  • 3Compute current_area = (right_index - left_index) * min(height[left_index], height[right_index])
  • 4Update max_area = max(max_area, current_area)
  • 5Move the pointer at the shorter line inward (the taller one cannot help)

4. How to Think About It

▶

Area of a container is width × min(left_height, right_height). The water level is capped by the shorter wall, because water spills over the shorter one.

Start with the widest container (first and last lines). It has the maximum possible width. To beat it, a narrower container would need a taller water level. The shorter of the two end lines cannot be part of a better container, because any narrower container using it has less width and the same (or lower) water-level cap. So the shorter line is safe to discard.

This is the greedy elimination: at each step, the shorter pointer is provably useless for any future better answer, so we move it inward. We never miss the optimal pair because we only discard lines that cannot be the bottleneck of a better container.

5. Real-World Analogy

▶

Imagine a row of fences of different heights, and you want to trap rainwater between two fences. The water level is set by the shorter fence, and the volume is that level times the distance between the fences.

You start with the two outermost fences (max distance). To do better, you need a taller water level, but the shorter outer fence cannot help, no matter what you pair it with, because it always caps the water. So you walk that shorter fence inward, hoping to find a taller partner.

Mappings: fences = height[i], distance between fences = right_index - left_index, water level = min(height[left_index], height[right_index]), move = walk the shorter fence inward.

Notice: we never move the taller pointer, because narrowing width while keeping the same cap cannot beat the current max.

8. How It Works (Step by Step)

▶
  • 1Initialize left_index = 0, right_index = len(height) - 1, max_area = 0
  • 2Compute width = right_index - left_index and water_level = min(height[left_index], height[right_index])
  • 3current_area = width * water_level; update max_area
  • 4If height[left_index] < height[right_index]: left_index += 1 else right_index -= 1
  • 5Repeat until left_index ≥ right_index; return max_area

10. From Brute Force to Optimal — Every Decision & Why

▶

v0 — Brute Force: check every pair

def maxArea(self, height: List[int]) -> int:
    max_area = 0
    for left_index in range(len(height)):
        for right_index in range(left_index + 1, len(height)):
            current_area = (right_index - left_index) * min(height[left_index], height[right_index])
            max_area = max(max_area, current_area)
    return max_area

Fails on: Large inputs. n = 10^5 → 10^10 pairs → TLE. Time O(n²), Space O(1).

v1 — Two pointers from ends (move shorter)

def maxArea(self, height: List[int]) -> int:
    max_area = 0
    left_index, right_index = 0, len(height) - 1
    while left_index < right_index:
        current_area = (right_index - left_index) * min(height[left_index], height[right_index])
        max_area = max(max_area, current_area)
        if height[left_index] > height[right_index]:
            right_index -= 1
        else:
            left_index += 1
    return max_area

Enhancement: Start widest, move the shorter pointer inward. Provably never misses the optimal pair because the shorter line cannot be the bottleneck of a better container. Time O(n), Space O(1).

Edge case handled: All inputs (including n = 2, all-equal heights, strictly increasing/decreasing). The loop invariant left_index < right_index guarantees termination.

v_final — Optimal (same as v1, self-explanatory names)

def maxArea(self, height: List[int]) -> int:
    max_area = 0
    left_index, right_index = 0, len(height) - 1
    while left_index < right_index:
        width = right_index - left_index
        water_level = min(height[left_index], height[right_index])
        current_area = width * water_level
        max_area = max(max_area, current_area)
        if height[left_index] < height[right_index]:
            left_index += 1
        else:
            right_index -= 1
    return max_area

Why final: O(n) time, O(1) space, handles every edge case. Extracted width and water_level as named intermediates for readability. This is the version used in Section 20.

11. Complexity Deep Dive

▶

Time: O(n)

Each step moves either left_index or right_index inward by one. The pointers start n-1 apart and meet after at most n-1 steps. Constant work per step (min, multiply, compare). Total: O(n).

Space: O(1)

Only three scalar variables: max_area, left_index, right_index (plus width/water_level in v_final). No extra arrays or data structures.

12. Edge Cases & Gotchas

▶
Two lines only (n = 2): Loop runs once, returns min(h0, h1) * 1. Correct.
All equal heights: Every step moves left (or right, depending on tie-break). Still O(n), max area = h * (n-1). Correct.
Strictly increasing: [1,2,3,4,5]. Left always shorter, left sweeps right. Correct.
Zero heights: [0,0,0]. Every area is 0, max stays 0. Correct (container holds nothing).
Width vs count bug: Width is right_index - left_index, NOT right_index - left_index + 1. The +1 counts lines, not distance on the x-axis.

13. Common Mistakes

▶
  • Using right - left + 1 for width (off-by-one, counts lines not distance)
  • Moving the taller pointer inward (loses the only chance to raise the water level)
  • Using max(height[l], height[r]) instead of min (water spills over the shorter wall)
  • Starting both pointers at 0 (not the widest container, loses the greedy invariant)
  • Forgetting to update max_area before moving pointers

14. Flashcards

▶

Q: Why move the shorter pointer, not the taller one?

A: The water level is capped by the shorter wall. Moving the taller wall inward only reduces width without raising the cap, so it can never improve the area. The shorter wall is provably useless for any better container.

Q: What is the width formula?

A: width = right_index - left_index. Not +1, because we measure distance on the x-axis, not count of lines.

Q: Time and space complexity?

A: O(n) time (each pointer moves at most n steps), O(1) space (three scalars).

Q: Why is the two-pointer approach correct (no missed optimal)?

A: Greedy elimination: the shorter line at any step cannot be part of a better container than the current widest, because any narrower pairing with it has less width and the same (or lower) cap. So discarding it never removes the optimal pair.

Q: How do you handle the tie when both heights are equal?

A: Either pointer can move. The condition height[left] < height[right] moves left on a tie (else branch moves right). Both choices are correct; the area formula is symmetric.

▶

  • Explain the greedy invariant aloud: "the shorter line cannot be part of a better container, so we discard it." This is the key insight interviewers want to hear.
  • Write the width formula as right - left, not right - left + 1. Say "distance, not count" to preempt the off-by-one.

19. Where This Pattern Meets System Design

▶

Load balancer bandwidth selection: Pick two endpoints to maximize throughput = min(bandwidth) × distance. The two-pointer greedy mirrors how a CDN picks the best edge pair for a user.

public int maxArea(int[] height) {
    int maxArea = 0;
    int leftIndex = 0, rightIndex = height.length - 1;
    while (leftIndex < rightIndex) {
        int width = rightIndex - leftIndex;
        int waterLevel = Math.min(height[leftIndex], height[rightIndex]);
        int currentArea = width * waterLevel;
        maxArea = Math.max(maxArea, currentArea);
        if (height[leftIndex] < height[rightIndex]) {
            leftIndex++;
        } else {
            rightIndex--;
        }
    }
    return maxArea;
}
