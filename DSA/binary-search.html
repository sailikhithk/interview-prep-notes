LEETCODE 704 EASY

Binary Search

Given a sorted array of integers nums and an integer target, return the index of target if it exists, otherwise return -1. The algorithm must run in O(log n) time.

Binary Search Array Divide & Conquer
TimeO(log n)
SpaceO(1)

1. Problem Statement

Write a function that searches for a target value in a sorted integer array. You must not use linear scan; the solution must run in logarithmic time by leveraging the sorted order.

Example
Input:
nums = [-1,0,3,5,9,12], target = 9
Output:
4

2. Pattern Recognition

expand

Core pattern: Sorted array + target lookup.

  • The input is sorted in a known order (ascending or descending).
  • You need to find a single element, a boundary, or an insertion point.
  • A linear scan would be too slow for large inputs.

3. Pattern Blueprint

expand
  1. 1Initialize two pointers: low and high.
  2. 2While the search space is valid, compute the middle index.
  3. 3Compare the middle element with the target.
  4. 4Discard the half that cannot contain the target.
  5. 5Return the answer when found or when the search space is exhausted.

4. How to Think About It

expand
1

Start with the whole array. The middle element is the pivot.

2

Ask: is the target to the left or right of the pivot? → One half is eliminated.

3

Repeat on the remaining half until the target is found or no elements remain.

5. Real-World Analogy

expand

Imagine looking up a word in a physical dictionary. You do not flip through every page from A to Z. Instead, you open the book near the middle, check whether your word comes before or after that page, and then repeat the process on the relevant half.

Mapping: the sorted dictionary pages are the sorted array; the middle page is mid; your word is the target.

6. Build Your Intuition

expand

Why is binary search O(log n)?

Each comparison cuts the remaining search space in half. After k steps, the space is n / 2^k. When n / 2^k = 1, k = log2(n).

What is the most common bug?

Using low < high instead of low <= high can skip the final element or miss the target entirely.

7. How It Works (Step by Step)

expand
  1. 1Set low = 0 and high = len(nums) - 1.
  2. 2While low <= high, compute mid = (low + high) // 2.
  3. 3If nums[mid] == target, return mid.
  4. 4If nums[mid] < target, set low = mid + 1.
  5. 5Otherwise, set high = mid - 1.
  6. 6If the loop ends, return -1.

10. Complexity Deep Dive

expand
Time: O(log n)

Each iteration halves the remaining elements. The number of iterations is bounded by log2(n).

Space: O(1)

Only three integer pointers are needed regardless of input size.

11. From Brute Force to Optimal

expand
Naive: Linear Scan

Check every element from left to right. O(n) time.

Optimal: Binary Search

Use the sorted order to discard half the elements each step. O(log n) time.

For n = 1,000,000, linear scan may do 1,000,000 comparisons; binary search does at most 20.

12. Edge Cases & Gotchas

expand
Empty array: Return -1 immediately. The low <= high loop never runs.
Single element: Only one element is checked. Using low < high would skip it.
Target absent: Loop ends with low > high; return -1.
Integer overflow: In languages with fixed-size ints, use low + (high - low) // 2.

13. Flashcards

expand
Q: What is the precondition for binary search?
A: The input must be sorted.
Q: What is the loop invariant?
A: If the target exists, it lies within [low, high].
Q: How many iterations for n = 1,000,000?
A: At most 20.

15. Common Mistakes

expand
Using low < high and missing the last element.
Applying binary search to an unsorted array.
Returning the value instead of the index.
Incorrect mid update: low = mid instead of low = mid + 1.

19. Where This Pattern Meets System Design

expand

Binary search mirrors the principle of logarithmic lookup used in distributed systems:

  • Consistent hashing: locating a key on a ring is a binary-search-like operation.
  • Database indexes: B-trees provide O(log n) lookups on disk.
  • Range partitioning: finding the correct shard for a sorted key space.

20. Code Solutions

expand
Python
def search(nums, target):
    low, high = 0, len(nums) - 1
    while low <= high:
        mid = (low + high) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1
Java
public int search(int[] nums, int target) {
    int low = 0, high = nums.length - 1;
    while (low <= high) {
        int mid = (low + high) >>> 1;
        if (nums[mid] == target) return mid;
        else if (nums[mid] < target) low = mid + 1;
        else high = mid - 1;
    }
    return -1;
}
TypeScript
function search(nums: number[], target: number): number {
    let low = 0, high = nums.length - 1;
    while (low <= high) {
        const mid = Math.floor((low + high) / 2);
        if (nums[mid] === target) return mid;
        if (nums[mid] < target) low = mid + 1;
        else high = mid - 1;
    }
    return -1;
}

21. Follow-Up Questions

expand
What if the array is sorted in descending order?
Reverse the comparison logic: if nums[mid] < target, move high instead.
How would you find the first or last occurrence of a duplicate target?
Once a match is found, continue searching in the relevant half instead of returning immediately.
Can you implement binary search recursively?
Yes, but the iterative version is preferred for O(1) space.
