Cyclic Shift Absolute Differences

Modular arithmetic · Array · Time O(n²) · Space O(n)

1. Problem Statement

You are given two integer arrays nums1 and nums2 of the same length n. For each cyclic right shift of nums1, compute the sum of absolute differences with nums2, and return the list of all such sums sorted in non-decreasing order.

Example:

nums1 = [1, 4, 2, 11], nums2 = [10, 1, 8, 4] → returns [7, 13, 25, 25]

Shift 0: |1-10|+|4-1|+|2-8|+|11-4| = 9+3+6+7 = 25. Shift 1: |11-10|+|1-1|+|4-8|+|2-4| = 1+0+4+2 = 7. Shift 2: 25. Shift 3: 13. Sorted: [7, 13, 25, 25].

▶

Key insight: For a right cyclic shift by shift, the element at position i in the shifted array comes from nums1[(i - shift) % n] in the original. This is modular index mapping — you compute the alignment without building the rotated array.

4. How to Think About It

▶

The first instinct is to physically rotate nums1 for each shift and compare. This works but wastes memory — you're allocating a new array of size n for each of n shifts. The key insight is that rotation is just an index transformation.

For a right cyclic shift by shift, the element that ends up at position i originally lived at position (i - shift) % n. Think of it as: "who moves into slot i?" The answer is the element shift positions to the left (wrapping around), which is (i - shift) % n.

The modulo handles the wrap-around. Python's % always returns a non-negative result for positive n, so (0 - 1) % 4 = 3 — correct. In languages where % can be negative (C++, Java), use ((i - shift) % n + n) % n to stay safe.

Once you have the index mapping, each shift is just a sum of n absolute differences. With n shifts, that's O(n²) total. The final sort is O(n log n), which is dominated by O(n²) for large n. The prompt explicitly allows O(n²), so this is the intended solution.

5. Real-World Analogy

▶

Two circular gears: Imagine two gears with numbers written on their teeth, both with n teeth. nums1 is on the top gear, nums2 on the bottom gear, fixed in place.

For each rotation of the top gear (right shift = turn the gear one tooth clockwise), you compute the total "mismatch" — the sum of absolute differences between the numbers now touching on each tooth pair. After checking all n rotations, you sort the mismatch scores.

Mapping:

  • nums1 = top gear (rotatable)
  • nums2 = bottom gear (fixed)
  • shift = how many teeth the top gear has rotated clockwise
  • absolute difference = mismatch at each tooth pair
  • modular index = "which tooth of the original gear is now at position i?"

You don't need to redraw the gear for each rotation — you just compute which tooth is where using modular arithmetic.

8. How It Works (Step by Step)

▶
1Outer loop: Iterate shift from 0 to n - 1. Each iteration computes one sum.
2Inner loop: For each position i from 0 to n - 1, compute original_index = (i - shift) % n. This is the index in the original nums1 that maps to position i after the right shift.
3Accumulate: Add abs(nums1[original_index] - nums2[i]) to the running sum for this shift.
4Store: After the inner loop, append the shift's sum to result.
5Sort: After all shifts, sort result in non-decreasing order and return it.

The (i - shift) % n formula is the heart. For right shift by 1, position 0 gets the element from index (0 - 1) % n = n - 1 — the last element moves to the front. That's exactly what "right cyclic shift" means.

10. From Brute Force to Optimal — Every Decision & Why

▶

v0 — Brute Force: physically rotate + compare

Time: O(n²) Space: O(n) per shift 
def solution_bruteforce(nums1, nums2):
    n = len(nums1)
    sums = []
    for shift in range(n):
        shifted = nums1[-shift:] + nums1[:-shift] if shift else nums1[:]
        current = 0
        for i in range(n):
            current += abs(shifted[i] - nums2[i])
        sums.append(current)
    sums.sort()
    return sums

Flaw: Allocates a new shifted array of size n for each of n shifts — O(n²) total memory allocations. The slicing nums1[-shift:] + nums1[:-shift] is Python-specific and hides the modular arithmetic. Works but wasteful and not portable to languages without slicing.

v_final — Modular index mapping, no array allocation

Time: O(n²) Space: O(n) 
def solution(nums1, nums2):
    n = len(nums1)
    result = []
    for shift in range(n):
        total_distance = 0
        for i in range(n):
            original_index = (i - shift) % n
            total_distance += abs(nums1[original_index] - nums2[i])
        result.append(total_distance)
    result.sort()
    return result

Why final: Same O(n²) time, but O(n) space total (only the result list). No intermediate arrays. The modular index (i - shift) % n is portable to any language. This is the version used in Section 20.

11. Complexity Deep Dive

▶

Time: O(n² + n log n) = O(n²) — The outer loop runs n times (one per shift). The inner loop runs n times (one per position). Total: n × n = n² operations. The final sort is O(n log n), which is dominated by O(n²) for n ≥ 2. The prompt explicitly allows O(n²), so this is optimal within the constraint.

Space: O(n) — The result list stores n sums. No intermediate arrays are allocated (modular indexing computes on the fly). The input arrays are not modified.

Why not O(n log n)? The absolute difference is not a linear operation, so FFT-based convolution doesn't apply directly. A prefix-sum approach would require sorting by value and tracking alignment changes, which is complex and doesn't clearly reduce the bound. The O(n²) solution is the intended one for this problem's constraints.

12. Edge Cases & Gotchas

▶
  • Single element (n=1): Only shift 0. Sum = |nums1[0] - nums2[0]|. Result = [that value].
  • Identical arrays: nums1 == nums2. Shift 0 gives sum 0. Other shifts give non-zero sums. Result starts with 0.
  • Right shift vs left shift: The problem says right cyclic shift. Right shift by shift means shifted[i] = nums1[(i - shift) % n]. If you use (i + shift) % n, that's a left shift — wrong answer.
  • Negative modulo in C++/Java: (i - shift) % n can be negative when i < shift. Use ((i - shift) % n + n) % n to ensure a non-negative index. Python's % is always non-negative for positive n, so no fix needed.
  • Forgetting to sort: The problem requires the result to be sorted in non-decreasing order. If you return the sums in shift order, you fail. Always call result.sort() before returning.

13. Common Mistakes

▶
  • Left shift instead of right shift: Using (i + shift) % n gives a left cyclic shift. The problem asks for right shift, so use (i - shift) % n. This is the #1 bug.
  • Forgetting the final sort: Returning sums in shift order [25, 7, 25, 13] instead of sorted [7, 13, 25, 25]. The problem says "sorted in non-decreasing order".
  • Building rotated arrays: Using nums1[-shift:] + nums1[:-shift] in Python works but hides the modular arithmetic and wastes memory. Use the index formula directly.
  • Negative indices in C++/Java: (i - shift) % n can be negative. Always normalize with ((i - shift) % n + n) % n in languages where % preserves sign.

14. Flashcards

▶
Q: What is the index formula for a right cyclic shift by shift?

shifted[i] = nums1[(i - shift) % n]. The element at position i after a right shift by shift comes from index (i - shift) % n in the original.

Q: Why is it (i - shift) and not (i + shift)?

A right shift moves elements to higher indices. So the element now at index i must have come from a lower index i - shift (wrapping around). (i + shift) would be a left shift.

Q: What is the time and space complexity?

Time O(n²) — n shifts × n comparisons each. Space O(n) — only the result list. The final sort is O(n log n), dominated by O(n²).

Q: Do you need to physically build each shifted array?

No. Modular index mapping (i - shift) % n lets you compute the alignment on the fly without allocating intermediate arrays. This saves memory and is portable across languages.

Q: What's the #1 bug to avoid?

Forgetting to sort the result before returning. The problem requires "sorted in non-decreasing order". Also: using + instead of - in the index formula (left shift vs right shift).

15. Where It Is Used (Real World)

▶

Signal alignment in communications: Two signal streams where one is cyclically shifted (due to timing offset). You compute the misalignment score for each shift to find the best alignment (the shift with the smallest sum of differences).

Image registration: Comparing two images where one is cyclically shifted (e.g., panoramic images). The "sum of absolute differences" is a similarity metric used to find the optimal shift alignment.

Rotational matching: Matching a pattern against a circular sequence (e.g., comparing two clock configurations, or DNA circular plasmids). Each rotation is a candidate alignment, and the SAD score ranks them.

19. Where This Pattern Meets System Design

▶

In a distributed system, this pattern maps to log alignment: two replicas have logs that may be offset by a rotation. You compute the misalignment score for each offset to find the best sync point.

Scale considerations:

  • For large n (millions), O(n²) is too slow. You'd need an approximate alignment via sampling or a domain-specific optimization.
  • If the arrays are sharded, each shard computes its local SAD, and the results are aggregated. But the shift is global, so sharding by position doesn't parallelize across shifts.
  • For streaming data, you'd maintain a running SAD per shift and update incrementally as new elements arrive — but this requires O(n) state per shift, which is O(n²) total.

public class Solution {
    public List<Integer> solution(int[] nums1, int[] nums2) {
        int n = nums1.length;
        List<Integer> result = new ArrayList<>();
        for (int shift = 0; shift < n; shift++) {
            int totalDistance = 0;
            for (int i = 0; i < n; i++) {
                int originalIndex = ((i - shift) % n + n) % n;
                totalDistance += Math.abs(nums1[originalIndex] - nums2[i]);
            }
            result.add(totalDistance);
        }
        Collections.sort(result);
        return result;
    }
}

21. Follow-Up Questions

▶
  • Can you do better than O(n²)? For absolute differences, not easily — |·| isn't linear, so FFT doesn't apply. If the values are bounded, you could sort indices by value and use prefix sums, but it's complex. For the stated bound, O(n²) is intended.
  • What if it's sum of squares instead of absolute differences? Then it's Σ(nums1[(i-shift)%n] - nums2[i])², which expands to a sum of products. That IS a convolution, and FFT gives O(n log n).
  • What if n is very large (10&sup6;)? O(n²) is 10¹² operations — too slow. You'd need an approximate solution: sample shifts, or use a domain-specific optimization (e.g., if values are bounded, bucket-sort and compute incrementally).
  • What if the arrays have different lengths? The problem says "same length n". If they differ, you'd need to define what "cyclic shift" means for unequal lengths — likely pad the shorter one or only compare overlapping positions.
